HyperParallel 模型适配流程 S0～S6
================================

整理依据

- 当前代码版本为 f8572d71，refactor(agent): isolate the RSI workflow under .agent。
- 总入口为 .agent/skills/hf-model-integration/SKILL.md。
- 该文件 Bring-up stage machine 表是阶段划分、交接产物和退出条件的依据。
- 下文的普通函数名、对象字段和调用顺序是便于阅读的伪代码组织。
- 每阶段先列阶段表直接要求，再给伪代码、引用展开及对应文件。
- 所有路径相对仓库根目录。代码块是流程说明，执行时以实际脚本参数为准。

动作约定

普通函数(输入) -> Agent 完成分析、编写、配置、检查等任务，返回结果。
SKILL(名称, 输入) -> 按指定 Skill 执行，返回其产物。
READ(路径, sections=章节) -> 阅读参考资料、模板或已有产物。
SCRIPT(路径, 参数) -> 执行脚本，取得退出码、输出及产物路径。
ASK(问题, 选项) -> 等待用户决定。
WRITE(路径, 内容) -> 持久化内容，返回文件路径。
SPAWN(任务, 输入) / WAIT(句柄) -> 委派任务及等待结果。

SPAWN/WAIT 是描述可选执行组织的符号。当前阶段表没有要求各阶段必须使用子 Agent。
if、for、while 表达控制流程。检查函数可返回缺失项列表，空列表表示通过。
return 将结果交给调用方，WRITE 将产物写入存储，两者可以使用同一份内容。
函数返回的逻辑对象可以包含实际文件路径。对象字段不代表脚本原本就返回同名 JSON。
SKILL 的输入表示任务和范围，具体执行过程需继续遵循该 Skill 的正文。
每阶段持久化产物的实际路径由运行配置确定，这里不规定额外的中文文件名。

主流程

fun 模型适配(任务, 运行目录) {
    // 主 Skill 要求按顺序推进，阶段产物作为下一阶段的接口。
    // 恢复时读取运行目录，定位第一个缺失的阶段产物，并核对当前资产版本。
    S0结果 = S0_调研规划(任务)
    if S0结果.状态 != "PASS" { return S0结果 }
    WRITE(任务.阶段产物路径.S0, S0结果)

    S1结果 = S1_适配实现(任务, S0结果.迁移规格)
    if S1结果.状态 != "PASS" { return S1结果 }
    WRITE(任务.阶段产物路径.S1, S1结果)

    S2结果 = S2_单节点正确性(任务, S0结果, S1结果)
    if S2结果.状态 != "PASS" { return S2结果 }
    WRITE(任务.阶段产物路径.S2, S2结果)

    S3结果 = S3_分布式等价(任务, S0结果, S1结果, S2结果)
    if S3结果.状态 != "PASS" { return S3结果 }
    WRITE(任务.阶段产物路径.S3, S3结果)

    S4结果 = S4_分析与优化(任务, S1结果, S3结果)
    if S4结果.状态 != "PASS" { return S4结果 }
    WRITE(任务.阶段产物路径.S4, S4结果)

    S5结果 = S5_验收集成(任务, S0结果, S1结果, S3结果, S4结果)
    WRITE(任务.阶段产物路径.S5, S5结果)
    if S5结果.状态 != "PASS" { return S5结果 }

    if 任务.要求形式验证 {
        S6结果 = S6_形式验证(任务, S5结果)
        WRITE(任务.阶段产物路径.S6, S6结果)
        return { 验收交付: S5结果, 形式验证: S6结果 }
    }
    return S5结果
}

S0～S5 按阶段推进，S6 是原阶段表中的可选形式验证阶段。
WRITE 记录的是已执行步骤的产物及其引用，不会将未运行步骤标为通过。
